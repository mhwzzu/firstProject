# 共同决策地图与足迹：体验深化设计

日期：2026-09-02

## 1. 目标

将当前“展示几张推荐卡”的首页升级为真正帮助两人决定去哪里吃、去哪里玩的共同决策地图。推荐必须能被用户控制、验证和追溯：用户既可用自然语言表达需求，也可编辑解析出的日期、预算、车程、偏好等条件；地图展示真实地点、距离、路线和天气，再用合规的内容证据解释“为什么此刻值得去”。

同时，将“心动标记—计划—到访—回忆”连接为连续状态。完成计划不再是静默写库，而是一次可补充照片、感受和评分的记录；记录最终出现在足迹地图和按行程分组的时间相册中。

## 2. 用户问题与产品原则

当前版本的不足是：天气/地点状态不可控，刷新缺乏显性条件，计划没有过程，完成后看不到回忆，推荐也没有足够的内容依据。新体验遵循以下原则：

1. **地图先于卡片。** 地点、距离、路线与地图状态是决策主界面；卡片用于解释和行动。
2. **输入先于刷新。** 刷新永远绑定一组可见、可编辑的约束，不做黑箱抽卡。
3. **隐式双人偏好。** 不设胜负式投票。每个账户的心动、略过、收藏、到访、评分和计划编辑都是独立信号；排序优先共同兴趣，并在长期内平衡双方不同偏好。
4. **事实与内容分层。** 天气、地点、路线、距离和营业状态必须有事实来源；外部内容只作为灵感证据，明确来源和更新时间，不能覆盖事实。
5. **记录应可回看。** 每次行程应成为一个可浏览的故事，而非隐形的数据库记录。

## 3. 共同决策地图

### 3.1 发起一次推荐

地图页顶端提供自然语言输入，例如“下周末想自驾两天，预算 2000，想看海，也想吃海鲜”。系统解析为可编辑条件芯片：

```text
当前位置 / 杭州 · 本周末 · 自驾 · 车程 ≤ 2.5 小时
预算 ≤ ¥2000 · 海边 · 海鲜
```

用户可直接编辑、删除或添加芯片，并点击“按这些条件更新”。默认使用浏览器授权的当前位置；用户拒绝授权、定位失败或主动切换时，退回个人常驻城市。系统不保存连续位置轨迹，只在本次推荐与路线计算中使用坐标。

### 3.2 地图和候选详情

刷新后，地图呈现 6–10 个候选标点，同时列出可上下滑动的候选卡。点击标点或卡片打开统一详情，包含：

- 名称、类别、位置、距离、预计车程、营业/开放状态、预算区间和天气适配；
- 两人偏好命中说明，以及“共同偏好”或“这次偏向照顾某位成员”的清晰表达；
- 推荐分项、事实数据来源、更新时间与地图跳转；
- 内容证据卡、想去、暂不考虑、加入周末计划等行动。

地图支持按“吃喝 / 周末旅行 / 室内 / 户外 / 车程 / 预算 / 已心动”筛选。推荐卡不能宣称没有数据来源的距离、价格、营业状态或实时天气。

## 4. 内容证据层

内容层的目标是提供“为什么值得去”的近期灵感，不是复制内容平台。

### 4.1 数据分层

| 层 | 内容 | 初始来源与约束 |
| --- | --- | --- |
| 事实层 | POI、坐标、路线、距离、天气、营业状态 | 高德等正式 API；显示更新时间 |
| 偏好层 | 心动、略过、到访、评分、计划编辑 | 应用内私有行为；按成员和空间隔离 |
| 内容证据层 | 季节提示、趋势摘要、来源链接、发布时间 | 仅接入正式授权 API、用户授权数据或合规搜索索引；显示来源与原链接 |

小红书、知乎、抖音、微博等页面不得成为未经许可的直接抓取目标。未来某个平台获得正式内容权限后，以独立 `InspirationSource` 适配器接入；适配器只输出标题、合规短摘要、发布时间、来源名、原链接和授权状态。应用不缓存整篇图文、视频或图片，不把外部内容当作路线/天气/价格事实。

### 4.2 刷新和降级

一次刷新生成带条件、数据来源、规则版本和时间戳的推荐快照。天气/地图失败时，显示“事实数据暂不可用”和最近有效结果的时间；内容源失败时，地图和规则推荐仍可使用；任意外部服务失败都不能用模型编造结果替代。

大模型只用于解析自然语言条件、归纳已验证候选的取舍和整理可编辑行程。模型不得新增地点，修改事实字段，或伪造攻略摘要与来源。

## 5. 双人心动状态和足迹

### 5.1 地图状态

地点在地图上处于以下一种主状态，并保留两个账户的独立信号：

| 状态 | 产生方式 | 作用 |
| --- | --- | --- |
| 推荐中 | 本次快照生成 | 临时候选，不直接改变长期偏好 |
| 心动/想去 | 任一成员保存 | 记录是谁心动，增加同类地点权重 |
| 已纳入计划 | 选择日期/行程 | 进入共同待办与路线编辑 |
| 已去足迹 | 到访后记录 | 形成回忆、抑制近期重复推荐 |

双方都心动的地点显示“共同想去”；单方心动地点保留为“为 TA 留下的灵感”；一方略过只影响其个人偏好，不能删除另一方的收藏。

### 5.2 从计划到回忆

计划包含日期、预算、地点顺序、备注和路线。行程结束后，状态转为“记录这次”，要求或引导用户补充至少一项内容：照片、简短感受、评分、实际花费或到访地点。提交后生成回忆组，而非只改变计划状态。

足迹页包含：

- **足迹地图**：按去过、想去、共同心动、计划中筛选，可按城市、年份、类别和成员信号查看。
- **时间相册**：按一次约会/旅行分组；每组有路线、地点、照片、文字、费用、当时的推荐理由和成员感受。

## 6. 架构与数据演进

前端拆分为地图决策页、条件编辑器、候选详情抽屉、内容证据卡、计划编辑器、足迹地图和相册时间线。地图库通过独立地图适配器封装，避免将高德 SDK 调用散落到组件中。

后端新增或扩展以下边界：

- `LocationContextService`：位置授权结果、城市回退、路线和天气上下文。
- `DecisionQuery`：自然语言原文、解析条件、可编辑条件、规则版本和快照。
- `InspirationSource`：可替换内容证据提供方；每项输出授权状态和来源元数据。
- `PlaceSignal`：成员对地点的心动、略过、收藏、到访和评分行为。
- `Journey` / `JourneyStop` / `MemoryAlbum`：替代当前只有标题的机械计划，表达完整行程和回忆组。

每个读取或写入操作都必须验证 `CoupleSpace` 成员权限。位置、外部内容授权令牌与照片访问使用最小化存储和最短必要保留期。

## 7. 交付分期

### 第一期：可控的共同决策地图

实现当前位置回退、城市/日期/预算/车程/标签条件、地图标点、地图详情、路线与天气、手动刷新、独立心动/略过信号、可追溯推荐快照和明确降级状态。此阶段不接入社交平台内容。

### 第二期：计划和足迹闭环

实现计划编辑、路线与地点顺序、到访记录、照片上传、回忆组、足迹地图和时间相册；保留原记忆数据的迁移路径。

### 第三期：合规内容情报和模型增强

接入至少一个正式批准的内容或搜索证据源；实现内容证据卡、来源状态、模型条件解析和基于候选的比较说明。任何内容源接入前必须完成授权、配额、版权展示和隐私评审。

## 8. 验收标准

1. 用户可在 30 秒内输入或编辑条件并得到带地图、距离/车程、天气状态、来源和更新时间的候选。
2. 用户拒绝定位、天气 API 失败或内容源失败时，地图仍能使用，并明确展示降级原因与最近数据时间。
3. 两个成员对地点的独立心动/略过操作只影响各自的偏好信号；共同心动可被地图与后续排序识别，且没有显式投票步骤。
4. 一次计划能录入多个地点并在到访后生成可在足迹地图和时间相册中找到的回忆组。
5. 外部内容卡均显示来源、时间和原链接；无授权平台内容不被抓取、复制或伪造成事实。
